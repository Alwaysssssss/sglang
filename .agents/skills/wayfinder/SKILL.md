一个松散想法已经出现，它太大，无法装入单个智能体会话，并且笼罩在迷雾中：从当前位置通往**目标**的路径尚不可见。路径探索的重点是找到道路，而不是直接冲向目标。本技能在仓库问题跟踪器上把道路绘制成**共享地图**，再逐个处理其中的**决策任务单**。这类任务单解决的是决策问题，而不是需要执行的构建切片，直到路线清晰。

每项工作的目标都不同，为目标命名是绘图的第一步，并决定每张任务单的形状。目标可以是一份交接后继续迭代的规格、规划前必须锁定的决策，或像数据结构迁移这样就地完成的改动。地图不限定领域，工程工作、课程内容或其他符合该形状的工作都可使用。

## 规划，而非执行

路径探索默认用于**规划**：每张任务单解决一个决策；当道路清晰、执行前不再有待决问题时，地图就完成了。想直接开始执行通常说明已经到达地图边缘，应当交接。某项工作可以在**笔记**中覆盖这一规则，把执行纳入地图本身；没有明确覆盖时，只产出决策，不产出交付物。

## 使用名称引用

每张地图和任务单都是问题单，因此都有一个**名称**，即其标题。在人类阅读的所有内容中，包括叙述和地图的“已有决策”，都通过名称引用，绝不只使用 ID、编号或 slug。满墙的 `#42, #43, #44` 无法阅读，名称则一目了然。ID 和 URL 不会消失，而是由名称包装成链接，始终位于名称*内部*，绝不代替名称。

## 地图

地图是当前仓库问题跟踪器中的单个问题单，带 `wayfinder:map` 标签，是规范产物。任务单是地图的子问题单。

地图是**索引**，不是存储。它列出已做决策并指向保存细节的任务单；每项决策只存在于一个位置，即其任务单。因此地图不重复表述决策，只提供一句摘要和链接。

**地图、子任务单、阻塞关系和前沿查询的实际位置取决于跟踪器。**应当已经配置问题跟踪器；如果没有，运行 `/setup-matt-pocock-skills`。查阅跟踪器文档的“路径探索操作”章节，了解*当前*仓库如何表示它们。未提供跟踪器时，默认使用本地 Markdown 跟踪器。

### 地图正文

地图以低分辨率展示全局，每个会话只加载一次。未关闭任务单**不会**列在正文中，它们是通过查询找到的未关闭子问题单。

```markdown
## 目标

<说明到达地图终点时的状态，即本项工作要寻找道路通往的规格、决策或改动。用一两行表达；每个会话选择任务单前都先据此确定方向。>

## 笔记

<领域；每个会话都应查阅的技能；本项工作的长期偏好>
```

### 任务单

每张任务单都是地图的**子问题单**，其身份由跟踪器问题单 ID 确定。正文只包含问题，规模控制在一个 10 万 token 的智能体会话内：

```markdown
## 问题

<本任务单要解决的决策或调查>
```

每张任务单都带一个 `wayfinder:<type>` 标签，类型为 `research`、`prototype`、`grilling`、`task` 之一，参见[任务单类型](#任务单类型)。

会话必须在任何工作开始**之前**，先将任务单分配给驱动地图的开发者来完成**领取**，使并发会话能够跳过。受理人*就是*领取标志：未关闭且没有受理人的任务单尚未领取。

阻塞使用跟踪器的**原生**依赖关系，因为它能在跟踪器界面中*直观*渲染前沿，使用户无需打开地图即可看到可领取内容。只有缺少原生阻塞的跟踪器才使用正文约定作为后备。阻塞当前任务单的所有任务单都关闭后，它才**解除阻塞**；**前沿**是所有未关闭、未阻塞、未领取的子项，也是已知范围的边缘。

答案不属于正文，而是在解决时记录，参见[逐步处理地图](#逐步处理地图)。解决任务单时创建的产物通过问题单链接，不要粘贴到正文。

## 任务单类型

每张任务单要么是**人在回路（HITL）**，即*与*能够代表自身发言的人类共同处理；要么是**无人值守（AFK）**，由智能体独立驱动。人在回路任务单只能通过实时交流解决；智能体绝不能代替人类一方发言。追问智能体自行回答问题就违反了规则。

- **调研**（无人值守）：阅读文档、第三方 API 或知识库等本地资源，查明决策依赖的事实。由 `/research` **子智能体**解决。需要当前工作目录之外的知识时使用。
- **原型**（人在回路）：制作低成本、粗糙而具体的产物来提高讨论保真度，例如大纲、粗略方案、桩，或通过 `/prototype` 技能创建界面/逻辑代码。把原型作为产物链接。关键问题是“外观如何”或“行为如何”时使用。
- **深入追问**（人在回路）：通过 `/grilling` 和 `/domain-modeling` 技能对话，一次提出一个问题。这是默认类型。
- **任务**（人在回路或无人值守）：做出*决策*前必须完成的手工工作。本身没有需要决策、制作原型或调研的内容，但不完成就会阻塞讨论。例如注册服务以评估其 API、配置访问权限、移动样本以查看形状。这是唯一负责*执行*而非决策的类型；它存在的价值是解除决策阻塞，而不是交付目标。能够独立完成时由智能体驱动，否则向人类提供精确清单。工作完成后解决任务单；答案记录所做工作及后续任务单依赖的事实，例如凭据位置、新 URL、条目数量。

## 战争迷雾

地图_有意_保持不完整：不要绘制尚不可见的内容。现有任务单之外是**战争迷雾**，其中能隐约看见即将出现的决策和调查，却因依赖尚未解决的问题而无法明确。解决一张任务单会清除前方迷雾，把已经可以明确的内容逐个转成新任务单，直到通往目标的道路清晰且没有剩余任务单。

地图的**尚未明确**章节记录这些模糊视图：疑似问题，以及稍后需要重访的区域。它是_朝向_目标的未发现前沿，其中所有内容都在范围内，只是还不够明确，无法形成任务单。根据当前视野尽可能松散或完整地记录；它也为协作者指示工作方向。

**迷雾还是任务单？**判断标准是现在能否精确陈述问题，_而不是_现在能否回答。

- **形成任务单：**问题已经清晰，即使受到阻塞、目前无法行动。
- **保持尚未明确：**还无法如此精确地表达。不要预先把迷雾切成任务单大小；它比任务单更粗糙，当前沿到达时，一块迷雾可能转成多张任务单，也可能一张都没有。

**尚未明确**不包括已经决定的内容（已有决策）、现有任务单和范围外内容（下一节）。

## 范围之外

迷雾只会聚集在_通往_目标的方向。目标固定范围，因此超出目标的工作属于**范围之外**，既不是迷雾，也不应放入**尚未明确**。地图使用独立的**范围之外**章节记录主动排除在_本项工作_之外的内容。决定其位置的是范围，而不是清晰度。

范围外工作永远不会转成任务单，因为前沿在目标处停止。只有重新绘制目标时才会返回，并且应作为全新工作，而不是恢复旧工作。

将某项内容排除在范围外是一项范围界定行为，不是路线中的一步。现有任务单被证明位于目标之外时，可能是绘图时误纳入，也可能是解决其他任务后才暴露；此时应**关闭它**，因为已关闭任务单明确不在前沿，并在**范围之外**章节留下一行：摘要、超出范围的原因，以及已关闭任务单链接。不要加入**已有决策**，该章节记录实际走过的路线，而范围边界不是路线中的一步。

## 调用方式

有两种模式。无论哪种模式，除调研任务单外，**每个会话绝不解决超过一张任务单**。

### 绘制地图

用户以松散想法调用。

1. **命名目标。**运行一次 `/grilling` 和 `/domain-modeling` 会话，明确地图要寻找道路通往的规格、决策或改动。目标决定范围，因此首先确定。
2. **绘制前沿。**再次追问，这次采用**广度优先**：在整个空间展开，而不是深入单个线程，找出待决问题和现在可以采取的第一步。**如果没有发现迷雾**，说明通往目标的道路已经清晰，整个过程可以在一个会话内完成，因此不需要地图。停止并询问用户希望如何继续。
3. **创建地图**并添加 `wayfinder:map` 标签：填入“目标”和“笔记”，“已有决策”保持为空，在**尚未明确**中勾勒迷雾。
4. 将**目前能够明确的内容创建为任务单**，作为地图的子问题单；再在**第二遍**连接阻塞边，因为问题单必须先有 ID 才能互相引用。连接后，任务单被分到前沿和阻塞集合；仍无法明确的内容留在迷雾，即**尚未明确**章节。
5. **启动调研子智能体。**为刚创建的每张 `research` 任务单启动一个 `/research` 子智能体并行解决，将发现保存在一次性 `research/<name>` 分支，并从任务单添加上下文指针。
6. 停止。绘制地图是一个会话的工作，不手动解决任何任务单。

### 逐步处理地图

用户使用地图 URL 或编号调用。任务单是**可选参数**；未指定时，由智能体而不是用户选择下一项决策。

1. 加载**地图**，只读取低分辨率全局视图，而不是每张任务单的正文。
2. 选择任务单。用户指定时使用指定项，否则按顺序选择第一张前沿任务单。任何工作开始前先**领取**，将其分配给自己。
3. 解决任务单并**按需放大**：需要时获取相关或已关闭任务单的完整正文；调用 `## 笔记` 区块中指定的技能。无法判断时使用 `/grilling` 和 `/domain-modeling`。
4. 记录解决结果：把答案发布为**解决评论**，**关闭**问题单，并向地图的“已有决策”**追加上下文指针**。
5. 添加新出现的任务单，先创建再连接；把答案使之明确的迷雾转成任务单，并从**尚未明确**中删除对应内容，使其只存在于新任务单中。如果答案表明当前或其他任务单位于目标之外，应将其**排除在范围外**，而不是作为路线的一部分解决。如果决策使地图其他部分失效，更新或删除相应任务单。

用户可能并行处理未阻塞任务单，因此应预期其他会话同时编辑跟踪器。
