# CONTEXT.md 格式

## 结构

```md
# {上下文名称}

{用一两句话说明这个上下文是什么以及为什么存在。}

## 语言

**订单**：
{用一两句话描述该术语}
_避免使用_：购买、交易

**发票**：
交付后向客户发送的付款请求。
_避免使用_：账单、付款申请

**客户**：
下达订单的个人或组织。
_避免使用_：顾客、买方、账户
```

## 规则

- **做出明确选择。**同一概念存在多个词语时，选择最佳术语，并将其他词列在 `_避免使用_` 下。
- **保持定义紧凑。**最多一两句话。定义它*是什么*，而不是它做什么。
- **只包含项目上下文特有的术语。**即使项目大量使用，超时、错误类型、工具模式等通用编程概念也不应加入。添加术语前先问：这是该上下文独有的概念，还是通用编程概念？只有前者符合条件。
- **自然形成聚类时使用子标题分组。**如果所有术语属于同一个紧密领域，则平铺列表即可。

## 单上下文与多上下文仓库

**单上下文（大多数仓库）：**在仓库根目录放置一个 `CONTEXT.md`。

**多上下文：**仓库根目录的 `CONTEXT-MAP.md` 列出各上下文的位置及彼此关系：

```md
# 上下文映射

## 上下文

- [订单](./src/ordering/CONTEXT.md) —— 接收并跟踪客户订单
- [计费](./src/billing/CONTEXT.md) —— 生成发票并处理付款
- [履约](./src/fulfillment/CONTEXT.md) —— 管理仓库拣货和发货

## 关系

- **订单 → 履约**：订单上下文发出 `OrderPlaced` 事件，履约上下文消费事件并开始拣货
- **履约 → 计费**：履约上下文发出 `ShipmentDispatched` 事件，计费上下文消费事件并生成发票
- **订单 ↔ 计费**：共享 `CustomerId` 和 `Money` 类型
```

技能按以下规则推断适用结构：

- 存在 `CONTEXT-MAP.md` 时，读取它以查找上下文；
- 只有根目录 `CONTEXT.md` 时，采用单上下文；
- 两者都不存在时，在第一个术语得到解决后按需创建根目录 `CONTEXT.md`。

存在多个上下文时，推断当前主题所属的上下文；无法确定时询问用户。
