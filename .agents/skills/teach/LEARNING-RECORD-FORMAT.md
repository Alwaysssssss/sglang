# 学习记录格式

学习记录位于 `./learning-records/`，使用连续编号，例如 `0001-slug.md`、`0002-slug.md`。按需创建目录，只在写入第一条记录时创建。

学习记录相当于教学中的 ADR：捕获将引导未来会话的非显然教训、关键洞察和用户说明的既有知识，并用于计算最近发展区。

## 模板

```md
# {所学或已确认内容的简短标题}

{用 1–3 句话说明学到了什么或确认了哪些既有知识，以及它为何会影响未来会话。}
```

完整格式到此为止。学习记录可以只有一个段落，其价值在于记录*现在已经掌握什么*以及*它为何改变下一步教学*，而不是填满章节。

## 可选章节

只有确实增加价值时才加入，大多数记录都不需要：

- **状态** frontmatter（`active | superseded by LR-NNNN`）—— 较早理解被证明有误并被替代时有用；
- **证据** —— 用户如何证明理解，例如回答问题、完成练习或说明既有经验。结论未来可能重审时有用；
- **影响** —— 为未来会话解锁或排除哪些内容。影响不明显时值得记录。

## 编号

扫描 `./learning-records/` 中的最大现有编号并加一。

## 何时编写学习记录

满足任一条件时编写：

1. **用户真正理解了非平凡内容。**不只是接触过，还要有能够正确使用概念的证据。这为下一步教学设定新的起点。
2. **用户说明了既有知识。**例如“我已经知道 X”。将其记录，避免未来会话重复教授，并记录用户声称的*深度*。
3. **纠正了误解。**用户之前持有错误认识，现在理解其原因。这类记录价值很高，能够预测相关主题中的未来障碍。
4. **使命因学习而改变。**用户发现真正关心的内容与原先不同。交叉链接到 `[[MISSION.md]]` 并更新它。

### 不符合条件的内容

- 仅仅讲过的材料。覆盖不等于学习，应等待证据。
- 已在 `[[GLOSSARY.md]]` 中作为术语定义紧凑记录的内容。不要重复。
- 逐会话活动日志。学习记录不是日记，而是决策级洞察。

## 替代关系

后续记录与早期记录冲突时，说明用户理解加深或得到纠正。不要删除旧记录，而应标记为 `Status: superseded by LR-NNNN`。理解如何演变的历史本身就是有用信号。
