# MISSION.md 格式

`MISSION.md` 位于工作区根目录，记录用户学习该主题的*原因*。每项教学决策，包括下一步教授什么、展示哪些资源、设计哪些练习，都应追溯到此文档。

## 模板

```md
# 使命：{主题}

## 原因
{用 1–3 句话说明用户追求的具体现实目标。获得这项技能后，生活或工作会发生什么变化？避免“理解 X”等抽象表述，应追问底层结果。}

## 成功表现
- {用户将能够完成的一项具体、可观察的事情}
- {另一项具体事情}
- {…}

## 约束
- {时间、预算、既有承诺、学习偏好，以及限制方法的任何因素}

## 范围之外
- {用户明确暂时不想追求的相邻主题，用于保护最近发展区}
```

## 规则

- **每个工作区只有一个使命。**用户希望学习两项不相关内容时，应使用两个工作区。
- **具体优于抽象。**“在十月前跑完半程马拉松”优于“变得更健康”；“向团队交付一个 Rust CLI”优于“学习 Rust”。
- **质疑模糊表述。**用户无法说明原因时，在写入任何内容前进行访谈。糟糕的使命比没有使命更差。
- **现实变化时修订。**使命会变化。用户目标移动时更新此文件，不要让过时使命继续引导未来会话。
- **保持简短。**`MISSION.md` 超过一屏时，就不再是指南针，而变成了计划。
