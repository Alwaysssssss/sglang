# 改进代码库架构

找出架构摩擦并提出**深化机会**，即把浅模块重构为深模块。目标是提高可测试性和智能体可导航性。

本命令以项目领域模型为依据，并建立在共享设计词汇之上：

- 运行 `/codebase-design` 技能获取架构词汇（**模块**、**接口**、**深度**、**接缝**、**适配器**、**杠杆率**、**局部性**）及其原则（删除测试、“接口就是测试表面”、“一个适配器是假想接缝，两个适配器是真实接缝”）。每条建议都严格使用这些术语，不要漂移到“组件”“服务”“API”或“边界”。
- `CONTEXT.md` 中的领域语言为良好接缝命名；`docs/adr/` 中的 ADR 记录本命令不应重新争论的决策。

## 流程

### 1. 探索

**扫描前先确定范围，遵循 YAGNI。**深化模块的收益来自简化未来改动，因此应提高近期频繁变动区域的权重。开始前先决定*查看哪里*：

- 如果用户指定了方向，例如模块、子系统或痛点，则按该方向探索，并跳过下面的推断。
- 否则，沿提交历史向前查看足够长的一段（`git log --oneline`），找出代码库热点，即反复出现的文件和区域，并优先关注这些路径。如果改动分散、没有明确热点，再扩大范围。

首先读取项目领域术语表（`CONTEXT.md`）以及所涉区域的 ADR。

然后使用 `Agent` 工具并设置 `subagent_type=Explore` 来浏览代码库。不要遵循僵硬的启发式规则，应自然探索并记录产生摩擦的位置：

- 哪些概念必须在许多小模块之间来回跳转才能理解？
- 哪些模块是**浅的**，接口几乎和实现一样复杂？
- 哪些纯函数只是为了可测试性而提取，但真实缺陷隐藏在调用方式中，缺少**局部性**？
- 哪些紧密耦合的模块跨接缝泄漏？
- 代码库的哪些部分没有测试，或难以通过当前接口测试？

对每个疑似浅模块执行**删除测试**：删除后复杂性会集中，还是只会移动？“会集中”正是所需信号。

### 2. 用 HTML 报告呈现候选项

将自包含 HTML 文件写入操作系统临时目录，避免在仓库中落盘。优先从 `$TMPDIR` 获取临时目录，失败时使用 `/tmp`，Windows 使用 `%TEMP%`。写入 `<tmpdir>/architecture-review-<timestamp>.html`，确保每次运行都生成新文件。为用户打开文件：Linux 使用 `xdg-open <path>`，macOS 使用 `open <path>`，Windows 使用 `start <path>`，并告知绝对路径。

报告通过 CDN 使用 **Tailwind** 完成布局和样式，并在图、流程或时序能够可靠表达结构时通过 CDN 使用 **Mermaid**。将 Mermaid 与手写 CSS/SVG 可视化混合使用：关系呈图状时，例如调用图、依赖或时序，使用 Mermaid；需要更具编辑感的质量图、剖面图或折叠动画时，使用手写 div/SVG。每个候选项都要有**改造前后可视化**。

为每个候选项渲染一张卡片，包含：

- **文件** —— 涉及哪些文件或模块；
- **问题** —— 当前架构为何产生摩擦；
- **方案** —— 用简明中文描述将发生的改动；
- **收益** —— 用局部性、杠杆率以及测试改进来说明；
- **改造前/后图** —— 并排自绘，展示浅模块及其深化结果；
- **推荐强度** —— 使用 `强烈推荐`、`值得探索`、`推测性建议` 之一，并渲染为徽章。

在报告末尾加入**首选建议**章节，说明优先处理哪个候选项及其原因。

**领域概念使用 `CONTEXT.md` 词汇，架构概念使用 `/codebase-design` 词汇。**如果 `CONTEXT.md` 定义了“订单”，应称为“订单接入模块”，而不是“FooBarHandler”或“订单服务”。

**ADR 冲突：**候选项与现有 ADR 冲突时，只有摩擦真实到值得重审 ADR 才应提出。必须在卡片中明确标记，例如警告框：“与 ADR-0007 冲突，但值得重审，因为……”。不要列出 ADR 禁止的每个理论重构。

完整 HTML 脚手架、图表模式和样式指南参见 [HTML-REPORT.md](HTML-REPORT.md)。

此时不要提出接口。文件写完后询问用户：“你想深入探索哪一个候选项？”

### 3. 深入追问循环

用户选择候选项后，运行 `/grilling` 技能，与用户共同遍历决策树：约束、依赖、深化模块的形状、接缝后的内容，以及应保留哪些测试。

决策形成时就地处理副作用，并运行 `/domain-modeling` 技能持续更新领域模型：

- **深化模块使用了 `CONTEXT.md` 中没有的概念命名？**将该术语加入 `CONTEXT.md`。文件不存在时按需创建。
- **对话中收紧了模糊术语？**立即更新 `CONTEXT.md`。
- **用户因关键理由拒绝候选项？**建议创建 ADR，并询问：“需要我把它记录为 ADR，避免未来架构审查再次提出吗？”只有未来探索者确实需要该理由才能避免重复建议时才提出；“现在不值得”等临时理由或不言自明的理由无需记录。
- **希望探索深化模块的备选接口？**运行 `/codebase-design` 技能，并使用其中“设计两次”的并行子智能体模式。
