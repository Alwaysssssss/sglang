# 逻辑原型

一个小型交互式终端应用，让用户手动驱动状态模型。用于涉及**业务逻辑、状态转换或数据形状**的问题，这类设计在纸面上看似合理，经过真实场景后才会显出问题。

## 适用场景

- “我不确定这个状态机能否处理先发生 X 再发生 Y 的边界场景。”
- “这个数据模型真的能表示……这种情况吗？”
- “编写之前，我想实际感受一下接口应是什么样子。”
- 用户希望**按下按键并观察状态变化**的任何情况。

如果问题是“它应该是什么样子”，说明选错了分支，应使用 [UI.md](UI.md)。

## 流程

### 1. 写明问题

编写代码前，写明要验证的状态模型和问题。在原型说明文件或文件顶部注释中用一个段落记录。回答错误问题的逻辑原型毫无价值，因此必须明确问题，使用户无论当前在线还是稍后返回，都能核对。

### 2. 选择语言

使用宿主项目已有语言。如果项目没有明显运行时，例如文档仓库，则询问用户。

遵循项目现有工具惯例，不要仅为原型添加新的包管理器或运行时。

### 3. 将逻辑隔离为可移植模块

将真正回答问题的逻辑放在一个小型纯接口后，使其日后能够直接提取并放入真实代码库。外围 TUI 是一次性的，逻辑模块则不应如此。

正确形状取决于问题：

- **纯 reducer** —— `(state, action) => state`。适合操作是离散事件、状态是单一值的情况。
- **状态机** —— 明确定义状态和转换。适合“当前允许哪些操作”也是问题一部分的情况。
- **作用于普通数据类型的一小组纯函数。**适合没有隐式当前状态、只有转换的情况。
- **具有清晰方法表面的类或模块。**适合逻辑确实拥有持续内部状态的情况。

选择最符合问题的形状，*而不是*最容易连接到 TUI 的形状。保持纯净：不做 I/O，不包含终端代码，不用 `console.log` 控制流程。TUI 导入并调用它，依赖不能反向流动。

这使原型在生命周期结束后仍有价值：问题得到回答后，经过验证的 reducer、状态机或函数集可独立提取到真实模块中。

### 4. 构建能够暴露状态的最小 TUI

将其构建为**轻量 TUI**：每个周期清空屏幕（`console.clear()`、`print("\033[2J\033[H")` 或等效方式），并重新渲染整个画面。用户应始终看到一个稳定视图，而不是不断增长的回滚内容。

每个画面按顺序包含两部分：

1. **当前状态**：美观打印且易于比较，每行一个字段或使用格式化 JSON。字段名和章节标题使用**粗体**，时间戳、ID、派生值等次要上下文使用**暗色**。可直接使用原生 ANSI 转义码：`\x1b[1m` 表示粗体，`\x1b[2m` 表示暗色，`\x1b[0m` 表示重置。除非项目已有样式库，否则无需引入。
2. **键盘快捷键**：列在底部，例如 `[a] 添加用户  [d] 删除用户  [t] 推进时钟  [q] 退出`。可以加粗按键、淡化说明，也可以反过来，以清晰易读为准。

行为：

1. **初始化状态** —— 使用单个内存对象或结构体，启动时渲染第一个画面。
2. 每次**读取一个按键或一行输入**，分派给改变状态的处理函数。
3. 每次操作后**重新渲染**完整画面，不追加内容，而是替换。
4. **循环直到退出。**

整个画面应适合单屏显示。

### 5. 用一条命令运行

向项目现有任务运行器（`package.json` 脚本、`Makefile`、`justfile`、`pyproject.toml`）添加脚本。用户只需运行 `pnpm run <prototype-name>` 或等效命令，不应记忆路径。

如果宿主项目没有任务运行器，在原型说明文件顶部写明命令。

### 6. 交给用户

向用户提供运行命令，由其亲自操作。最有价值的时刻是用户说“等等，这不应该发生”或“原来 X 和我想的不一样”，这些就是*想法*中的缺陷，也是原型的全部意义。用户希望添加新操作时直接添加；原型会持续演化。

### 7. 保存答案和原型

原型回答问题后，先记录答案，再按 [SKILL](SKILL.md) 的说明保存原型。逻辑分支的对应关系是：把经过验证的 reducer、状态机或函数集提取到真实模块中，吸收决策；TUI 外壳则随原型保存在一次性分支，作为一手来源。

## 反模式

- **不要添加测试。**需要测试的原型已不再是原型。
- **不要连接到真实持久化环境。**除非问题专门涉及持久化，否则使用内存存储。
- **不要泛化。**不讨论“以后如果要支持 X 怎么办”。原型只回答一个问题。
- **不要混合逻辑和 TUI。**如果 reducer 或状态机引用 `console.log`、提示符或终端转义码，就不再可移植。让 TUI 只作为纯模块上的薄外壳。
- **不要把 TUI 外壳交付到生产环境。**外壳针对人工终端操作优化，真正值得保留的是其背后的逻辑模块。
