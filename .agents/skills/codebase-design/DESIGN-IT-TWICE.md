# 设计两次

当用户希望为选定的深化候选项探索备选接口时，使用这一并行子智能体模式。该模式源于 Ousterhout 的“设计两次”：第一个想法通常不会是最佳方案。

使用 [SKILL.md](SKILL.md) 中的词汇：**模块**、**接口**、**接缝**、**适配器**、**杠杆率**。

## 流程

### 1. 界定问题空间

启动子智能体之前，为选定候选项编写一份面向用户的问题空间说明：

- 新接口必须满足的约束；
- 它依赖的内容及其所属分类，参见 [DEEPENING.md](DEEPENING.md)；
- 一份用于落实约束的粗略示意代码。它不是方案，只用于使约束具体化。

向用户展示后立即进入第 2 步。用户阅读和思考的同时，让子智能体并行工作。

### 2. 启动子智能体

使用 `Agent` 工具并行启动至少 3 个子智能体。每个子智能体都必须为深化后的模块设计一个**截然不同**的接口。

向每个子智能体提供独立的技术简报，包括文件路径、耦合细节、[DEEPENING.md](DEEPENING.md) 中的依赖分类，以及接缝背后的内容。简报独立于第 1 步面向用户的问题空间说明。为每个智能体设置不同的设计约束：

- 智能体 1：“最小化接口，最多设置 1–3 个入口，并最大化每个入口的杠杆率。”
- 智能体 2：“最大化灵活性，支持多种用例和扩展。”
- 智能体 3：“针对最常见调用方优化，使默认情况极其简单。”
- 智能体 4（如适用）：“围绕端口与适配器设计跨接缝依赖。”

在简报中同时包含 [SKILL.md](SKILL.md) 和 `CONTEXT.md` 的词汇，使每个子智能体的命名同时符合架构语言和项目领域语言。

每个子智能体输出：

1. 接口，包括类型、方法、参数，以及不变量、顺序和错误模式；
2. 展示调用方如何使用接口的示例；
3. 实现在接缝后隐藏的内容；
4. 依赖策略和适配器，参见 [DEEPENING.md](DEEPENING.md)；
5. 取舍，包括杠杆率高和较薄弱的位置。

### 3. 展示并比较

依次展示设计，让用户逐个理解，再用文字进行比较。对比维度为**深度**（接口杠杆率）、**局部性**（改动集中位置）和**接缝位置**。

比较后给出明确建议：说明哪个设计最强及其原因。如果不同设计中的元素适合组合，提出混合方案。要有明确立场；用户需要有力判断，而不是一份菜单。
