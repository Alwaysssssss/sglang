# 深化

如何根据依赖安全地深化一组浅模块。本文采用 [SKILL.md](SKILL.md) 中的词汇：**模块**、**接口**、**接缝**、**适配器**。

## 依赖分类

评估深化候选项时，先对其依赖进行分类。分类决定如何跨接缝测试深化后的模块。

### 1. 进程内依赖

只包含纯计算和内存状态，没有 I/O。始终可以深化：合并模块，并直接通过新接口测试，无需适配器。

### 2. 本地可替代依赖

拥有本地测试替身的依赖，例如用 PGLite 替代 Postgres、用内存文件系统替代真实文件系统。存在替身时可以深化。测试套件运行该替身来测试深化后的模块。接缝位于内部，无需在模块外部接口上设置端口。

### 3. 自有远程依赖（端口与适配器）

跨网络调用的自有服务，例如微服务和内部 API。在接缝处定义一个**端口**（接口）。深模块拥有逻辑，传输机制以**适配器**形式注入。测试使用内存适配器，生产环境使用 HTTP、gRPC 或队列适配器。

推荐表述：*“在接缝处定义端口，为生产环境实现 HTTP 适配器，为测试实现内存适配器。即使跨网络部署，逻辑仍集中在一个深模块中。”*

### 4. 真正的外部依赖（模拟）

无法控制的第三方服务，例如 Stripe、Twilio。深化后的模块将外部依赖作为注入端口接收，测试提供模拟适配器。

## 接缝纪律

- **一个适配器意味着假想接缝，两个适配器意味着真实接缝。**除非至少两个适配器确有必要，通常是生产与测试适配器，否则不要引入端口。只有一个适配器的接缝只是间接层。
- **内部接缝与外部接缝。**深模块既可以拥有实现私有、供自身测试使用的内部接缝，也可以在接口处拥有外部接缝。不要仅仅因为测试使用内部接缝，就通过接口将其暴露。

## 测试策略：替换，不叠加

- 深化模块接口上的测试建立后，浅模块的旧单元测试便成为冗余，应将其删除。
- 在深化模块的接口处编写新测试。**接口就是测试表面。**
- 测试通过接口断言可观察结果，而不是内部状态。
- 测试应能经受内部重构，因为它描述行为而非实现。如果实现变化时测试也必须变化，说明测试越过了接口。
