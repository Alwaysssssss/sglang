# 向导

**向导**是一个 Bash 脚本，逐步引导用户完成既不适合纯手工执行、也不值得每次都重新向 AI 解释的人工流程。它会打开各个 URL，准确说明要点击和复制什么，采集对应值并写入正确位置（`.env`、GitHub 密钥），在每个阶段进行确认，并显示剩余进度。它可以配置第三方服务、执行一次性迁移，或将项目从一种状态转换到另一种状态。

[template.sh](template.sh) 已经解决了顺畅的用户体验：显示进度和剩余时间、提供确认关卡、跨平台打开 URL（包括 WSL）、隐藏密钥输入、幂等更新 `.env`、写入 `gh secret` 或 `gh variable`，以及最终总结。**你的任务只是界定流程范围并编写各阶段。** 每个向导中 `STAGES` 标记上方的库都完全相同；一致性正是设计目标，绝不要手动编辑它。

向导默认是临时产物——为单次运行构建，保存到临时位置或 `scripts/` 路径，工作完成后删除。只有用户需要仓库长期保留可重复配置路径时才提交。

## 流程

### 1. 界定流程范围

梳理用户必须执行的每个人工步骤，以及过程中采集的每个值。先阅读仓库，不要毫无背景地询问：

- 对于配置：检查 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`（每个 `secrets.*` 或 `vars.*` 引用都是向导必须产出的值）。
- 对于迁移或转换：明确当前状态、目标状态，以及二者之间不可逆的操作。

然后向用户展示有序阶段列表及每个阶段产出的值，并请求确认；用户可以添加、删除或重新排序。

**完成条件：** 每个阶段都已按顺序命名，并且对于每个采集值都已明确：(a) 用户从哪里获取；(b) 写入哪里（`.env`、GitHub 密钥、两者，或不写入任何位置——有些阶段只是执行操作）；(c) 它是密钥（隐藏输入）还是公开值。

### 2. 绘制每个阶段的操作路径

为每个阶段写出用户要遵循的准确路径：打开哪个 URL、在页面上做什么、值显示在哪里、填入哪个变量——例如“控制台 → 开发者 → API 密钥 → 显示测试密钥 → 复制”。如果并不确定当前界面或准确命令，明确说明，并询问用户或查阅文档；绝不要编造可能不存在的步骤。

**完成条件：** 每个阶段都有陌生用户也能照做的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。按依赖顺序，用每个步骤对应的一个 `stage` 替换示例阶段。使用库辅助函数——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并将 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设置为诚实的估算值（它们驱动剩余时间显示）。

保持模板设定的质量标准：询问值之前先打开 URL；所有密钥都使用 `ask_secret`；每个持久化值都使用 `write_env`；只为 CI 确实需要的值调用 `set_secret`；任何不可逆操作前都调用 `confirm`。每个 `stage` 都会清屏，只显示当前步骤；每个阶段只聚焦一项任务，避免用户需要的内容滚出屏幕。不要修改标记上方的库。

### 4. 验证并交付

- 运行 `bash -n <脚本>`；如果可用，再运行 `shellcheck`。
- 运行 `chmod +x <脚本>`。
- 不要自行端到端运行——它会打开浏览器并阻塞等待人工输入。改为静态跟踪：确认步骤 1 中的每个值都被采集并写入约定位置，且每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全匹配。
- 告知用户如何运行。如果它是可重复的配置路径，则提交脚本并从 README 链接，使下一位用户直接运行脚本，而不是再次询问 AI。
